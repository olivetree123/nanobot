# nanobot 符合 ReAct 思想吗
nanobot 在核心设计上符合 ReAct 思想，但有一些重要的区别和扩展。

## 什么是 ReAct

ReAct（Reasoning + Acting）是 Yao et al. 2022 年提出的框架，核心循环是：

```
Thought → Action → Observation → Thought → ...
```

## nanobot 与 ReAct 的对应关系

`AgentRunner.run()` 的迭代循环与 ReAct 高度对应：

| ReAct 概念 | nanobot 实现 |
|-----------|-------------|
| **Thought** | LLM 响应中的 `response.content` 和 `reasoning_content` |
| **Action** | `response.tool_calls` — 工具调用请求 |
| **Observation** | `role: "tool"` 消息 — 工具执行结果 |
| **循环** | `for iteration in range(max_iterations)` |

系统提示中也明确体现了 ReAct 的"先行动再推理"原则：

> Act, don't narrate. If you can do it with a tool, do it now — never end a turn with just a plan or promise.
> 翻译：行动，不要叙述。如果能用工具完成，现在就用——永远不要只用计划或承诺来结束一个回合。

## 与原始 ReAct 的区别

**1. 实现方式不同**

原始 ReAct 使用纯文本格式（`Thought: ... Action: ... Observation: ...`），nanobot 使用现代 LLM 的 **tool calling API**（OpenAI function calling / Anthropic tool use），Thought 和 Action 是结构化分离的。

**2. 并发工具执行**

原始 ReAct 是顺序的（一次一个 Action），nanobot 支持并发执行多个工具：

```python
results, new_events, fatal_error = await self._execute_tools(
    spec,
    response.tool_calls,  # 可以是多个工具
    external_lookup_counts,
)
```

**3. 额外的工程增强**

- **Mid-turn injection**：用户可以在 AI 推理过程中注入新消息，这是 ReAct 没有的
- **内存系统**（Consolidator / AutoCompact / Dream）：长期记忆管理
- **上下文治理**：历史裁剪、孤立结果清理等

**4. 支持 Chain-of-Thought 推理**

nanobot 支持 Anthropic 的 extended thinking 和 OpenAI 的 reasoning_effort，`reasoning_content` 字段保存内部推理过程，这是对 ReAct 中 Thought 步骤的强化。

## 总结

nanobot 本质上是 **ReAct 思想的现代工程实现**：用 tool calling API 替代了文本格式的 Thought/Action/Observation，并在此基础上增加了并发工具执行、内存管理、会话隔离等生产级特性。它不是学术意义上的 ReAct 复现，而是将 ReAct 的核心思想融入了一个完整的多渠道 AI 助手框架中。
