# 问题：mid-turn injection 是什么意思？

Mid-turn injection 是 nanobot 的一项核心机制，允许用户在 AI 正在处理消息时发送后续消息，这些消息会被无缝注入到当前对话回合中，而不是创建竞争的处理任务。

## 核心概念

当 AI 正在生成回复或执行工具时，如果用户发送新消息，mid-turn injection 机制确保这些新消息能够被当前处理任务接收并响应，避免产生多个并发的 AI 回复。

## 实现机制

### 1. 消息路由决策

在 `AgentLoop.run()` 的主循环中，系统首先计算有效的会话键，然后检查该会话是否已有活跃的处理任务 ：

```python
effective_key = self._effective_session_key(msg)
# If this session already has an active pending queue (i.e. a task
# is processing this session), route the message there for mid-turn
# injection instead of creating a competing task.
if effective_key in self._pending_queues:
    self._pending_queues[effective_key].put_nowait(pending_msg)
```

### 2. 待处理队列管理

每个活跃会话都维护一个容量为 20 的待处理队列：

```python
pending = asyncio.Queue(maxsize=20)
self._pending_queues[session_key] = pending
```

### 3. 注入回调执行

在 `_run_agent_loop` 中定义的 `_drain_pending` 函数负责从队列中取出注入消息 ：

```python
async def _drain_pending(*, limit: int = _MAX_INJECTIONS_PER_TURN) -> list[dict[str, Any]]:
    """Non-blocking drain of follow-up messages from the pending queue."""
    # 处理队列中的消息并转换为标准格式

```

### 4. AgentRunner 集成

AgentRunner 在多个关键点检查注入消息：工具执行后、最终响应后、错误发生时 ：

```python
should_continue, injection_cycles = await self._try_drain_injections(
    spec, messages, assistant_message, injection_cycles,
    phase="after final response",
    iteration=iteration,
)
```

## 防护机制

为防止无限循环，系统设置了最大注入周期限制 ：

```python
if injection_cycles >= _MAX_INJECTION_CYCLES:
    return False, injection_cycles
```

## 实际效果

- **保持对话连贯性**：用户可以在 AI 思考时补充信息或修正
- **避免重复响应**：防止同一会话产生多个并行的 AI 回复
- **支持流式响应**：即使在流式输出过程中也能接收新消息

## Notes

- 队列满时会回退到创建新任务处理
- 统一会话模式下，所有渠道共享同一个注入机制
- 测试显示该机制能正确处理多媒体内容和多轮注入
