# 沙箱会挂载宿主机的目录吗

沙箱挂载的是容器内的目录，而不是宿主机的目录。
> 在 Linux 宿主机上直接部署时，bwrap 沙箱会直接挂载宿主机的实际目录

---

## 沙箱挂载机制

沙箱通过 bubblewrap 的 `--bind` 和 `--ro-bind` 参数挂载目录，这些路径都是相对于容器内部的文件系统：

| 挂载类型 | 路径 | 说明 |
|---------|------|------|
| `--bind` | 工作区目录 | 读写挂载，如 `/home/nanobot/.nanobot/workspace`  |
| `--ro-bind-try` | 媒体目录 | 只读挂载，如 `/home/nanobot/.nanobot/media`  |
| `--ro-bind` | 系统目录 | 只读挂载 `/usr`, `/bin`, `/lib` 等  |
| `--tmpfs` | 工作区父目录 | 掩蔽配置目录，隐藏 `config.json` |

## Docker 部署时的目录映射

在 Docker 环境中，宿主机目录通过 Docker volume 映射到容器内，然后沙箱再挂载容器内的目录：

```mermaid
graph LR
    Host["宿主机 ~/.nanobot"]
    Container["容器 /home/nanobot/.nanobot"]
    Sandbox["bwrap 沙箱"]
    
    Host -- "Docker volume 挂载" --> Container
    Container -- "bwrap --bind" --> Sandbox
```

例如，Docker 运行命令中的 `-v ~/.nanobot:/home/nanobot/.nanobot` 将宿主机的配置目录挂载到容器内，然后沙箱再将容器内的 `/home/nanobot/.nanobot/workspace` 挂载为读写。

## Notes

- 沙箱只能看到容器内的文件系统，无法直接访问宿主机的其他目录
- 如果需要在宿主机和容器之间共享文件，必须通过 Docker 的 volume 挂载机制实现
- 沙箱使用 `--tmpfs` 掩蔽工作区的父目录，防止读取容器内的 `config.json`
