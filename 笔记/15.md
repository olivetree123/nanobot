# templates 目录下有很多markdown 文件，这些文件有什么作用？
templates 目录下的文件分为两类，作用完全不同：

## 第一类：Jinja2 提示词模板（`agent/` 目录）

这些文件通过 `render_template()` 函数渲染，作为 LLM 的系统提示 。底层使用 Jinja2 引擎，支持变量插值（`{{ var }}`）和条件逻辑（`{% if %}`）。

| 文件 | 用途 |
|------|------|
| `identity.md` | 主 Agent 的核心身份提示，包含运行时信息、工作区路径、执行规则、渠道特定格式提示 |
| `platform_policy.md` | 平台特定策略（macOS/Linux/Windows 的文件系统差异等），被 `identity.md` include |
| `dream_phase1.md` | Dream Phase 1 的系统提示，指导 LLM 分析历史并识别需要更新的内容 |
| `dream_phase2.md` | Dream Phase 2 的系统提示，指导 LLM 编辑内存文件 |
| `evaluator.md` | 后台任务结果评估提示，决定是否需要通知用户 |
| `skills_section.md` | 技能列表部分的提示，注入到系统提示中 |
| `subagent_system.md` | 子代理的系统提示 |
| `subagent_announce.md` | 子代理完成任务后向主 Agent 发送通知的消息模板 |
| `_snippets/untrusted_content.md` | 可复用片段，通过 `{% include %}` 被其他模板引入 |

例如，`identity.md` 根据渠道类型动态调整格式提示，`evaluator.md` 根据 `part` 参数渲染不同内容。

## 第二类：工作区初始化模板（根目录和 `memory/`）

这些文件是用户可编辑的配置文件的**初始模板**，首次运行时复制到工作区。`ContextBuilder` 将它们作为 bootstrap 文件加载到系统提示中：

| 文件 | 用途 |
|------|------|
| `SOUL.md` | 机器人个性的初始模板，定义 nanobot 的行为风格 |
| `USER.md` | 用户信息的初始模板，包含姓名、时区、偏好等占位符 |
| `AGENTS.md` | 代理指令，说明如何使用 cron 和 heartbeat 功能 |
| `TOOLS.md` | 工具使用说明，记录各工具的非显而易见的约束和用法 |
| `HEARTBEAT.md` | 心跳任务文件的初始模板 |
| `memory/MEMORY.md` | 长期记忆文件的初始模板 |

这两类文件的关键区别：
- **`agent/` 下的文件**：代码内部使用，用户不直接编辑，通过 `render_template()` 渲染后注入 LLM 提示
- **根目录下的文件**：复制到工作区后由用户自由编辑，是定制 nanobot 行为的主要入口


## 加载方式

`SOUL.md` 是 `ContextBuilder.BOOTSTRAP_FILES` 列表中的一员：

```python
BOOTSTRAP_FILES = ["AGENTS.md", "SOUL.md", "USER.md", "TOOLS.md"]
```

`_load_bootstrap_files()` 方法从工作区读取这些文件，拼接成字符串：

```python
for filename in self.BOOTSTRAP_FILES:
    file_path = self.workspace / filename
    if file_path.exists():
        content = file_path.read_text(encoding="utf-8")
        parts.append(f"## {filename}\n\n{content}")
```


## 注入位置

`build_system_prompt()` 将 bootstrap 文件内容（包含 `SOUL.md`）作为系统提示的第二部分注入：

```
系统提示结构：
├── identity.md（核心身份、执行规则、平台策略）
├── AGENTS.md + SOUL.md + USER.md + TOOLS.md（bootstrap 文件）
├── Memory（MEMORY.md 内容）
├── Active Skills（always-on 技能）
├── Skills Summary（可用技能列表）
└── Recent History（未处理的历史条目）
```

最终通过 `build_messages()` 将系统提示作为 `role: "system"` 消息传给 LLM。
