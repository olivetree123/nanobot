# `AgentRunner.run` 执行流程

`AgentRunner.run` 是 nanobot 的核心执行方法，负责运行支持工具的 LLM 交互循环，处理从初始消息到最终响应的完整流程。

## 执行流程概览

```mermaid
graph TD
    A[run方法开始] --> B[初始化状态和钩子]
    B --> C[主循环 for iteration in range(max_iterations)]
    C --> D[上下文治理]
    D --> E[调用LLM获取响应]
    E --> F{有工具调用?}
    F -->|是| G[执行工具]
    F -->|否| H[处理最终响应]
    G --> I[检查注入消息]
    H --> I
    I --> J{需要继续?}
    J -->|是| C
    J -->|否| K[返回结果]
```

## 详细执行步骤

### 1. 初始化阶段

方法开始时初始化所有必要的状态变量：
- 设置钩子（hooks）
- 复制初始消息
- 初始化使用量统计、工具列表等
- 设置重试计数器和注入周期计数器

### 2. 主循环迭代

进入主循环，最多执行 `max_iterations` 次 。

#### 上下文治理
每次迭代开始时，对消息进行上下文治理：
- 清理孤立工具结果
- 补充缺失的工具结果
- 微压缩历史消息
- 应用工具结果预算
- 裁剪历史以适应上下文窗口

#### LLM 请求
调用 `_request_model` 方法获取 LLM 响应：
- 构建请求参数
- 支持流式和非流式响应
- 累计使用量统计

### 3. 工具执行处理

如果响应包含工具调用：
1. 结束当前流式响应（如果有）
2. 构建助手消息并添加到历史
3. 发出检查点（awaiting_tools）
4. 执行工具调用
5. 处理工具结果和可能的致命错误
6. 发出检查点（tools_completed）
7. 检查并处理注入消息

### 4. 最终响应处理

如果没有工具调用，处理最终响应：
1. 通过钩子最终化内容
2. 处理空响应（最多重试2次）
3. 检查并处理注入消息
4. 处理 LLM 错误

### 5. 注入消息处理

在多个关键点检查并处理中途注入的消息：
- 工具执行后
- 最终响应后
- 错误发生时
- 达到最大迭代次数后

### 6. 循环结束与结果返回

循环结束的原因可能包括：
- 正常完成
- 达到最大迭代次数
- 发生错误
- 工具执行错误

最终返回 `AgentRunResult` 包含执行结果。

## 关键特性

### 错误恢复机制
- 空响应重试：最多2次静默重试
- 上下文治理失败时使用最小修复
- 工具执行失败时的处理策略

### 并发控制
- 支持并发工具执行
- 外部查找计数限制重复调用

### 检查点机制
- 在关键状态变化时发出检查点
- 支持运行时状态恢复

## Notes

- AgentRunner 是无状态的，每次 `run` 调用都是独立的
- 通过钩子机制扩展功能，如流式响应、进度回调等
- 测试覆盖了各种边界情况，包括错误恢复、注入处理等
