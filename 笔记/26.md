# 沙箱
nanobot 使用 **bubblewrap (bwrap)** 作为沙箱机制来隔离 shell 命令的执行，提供内核级别的安全隔离。

## 沙箱配置

在配置文件中设置 `"tools.exec.sandbox": "bwrap"` 来启用沙箱：

```json
{
  "tools": {
    "exec": {
      "sandbox": "bwrap"
    }
  }
}
```

## 沙箱隔离机制

当启用 bwrap 沙箱时，`wrap_command` 函数会包装 shell 命令，创建一个容器化的环境：

| 目录/路径 | 挂载方式 | 说明 |
|-----------|---------|------|
| 工作区目录 | 读写 (RW) | 代理可以正常工作  |
| 媒体目录 | 只读 (RO) | 可以读取上传的附件  |
| 系统目录 (`/usr`, `/bin`, `/lib`) | 只读 (RO) | 命令仍然可以正常工作  |
| 配置文件和 API 密钥 | 隐藏 (tmpfs) | 使用 tmpfs 掩蔽，防止读取敏感信息  |

## Docker 部署要求

在 Docker 中使用沙箱需要特定的 Linux 能力：

- `cap_add: [SYS_ADMIN]` - 允许 bwrap 创建命名空间
- `cap_drop: [ALL]` - 移除所有其他能力
- `security_opt: apparmor=unconfined, seccomp=unconfined` - 禁用会阻止 bwork 的限制

## 平台限制

bwrap 沙箱**仅在 Linux 上可用**，因为它依赖 Linux 内核命名空间。  在 macOS 或 Windows 上无法使用。

## 自动启用限制

启用沙箱会自动激活 `restrictToWorkspace`，将文件工具限制在工作区内。 

## Notes

- 沙箱配置在 `ExecToolConfig` 类中定义，`sandbox` 字段默认为空字符串
- 官方 Docker 镜像已预装 bubblewrap
- WebUI 配置界面中显示为 "Exec sandbox" 选项
