# AutoCompact 工作过程详解

### 整体设计

AutoCompact 是**主动式**会话压缩机制，在用户空闲时将旧消息总结归档，减少下次对话时的 token 消耗。它不使用定时器，而是寄生在 AgentLoop 主循环的空闲时间中运行。

---

### 第一步：触发检查（每 ~1 秒）

`AgentLoop.run()` 主循环每次消费消息超时（1秒）时，调用 `check_expired()`：

```python
while self._running:
    try:
        msg = await asyncio.wait_for(self.bus.consume_inbound(), timeout=1.0)
    except asyncio.TimeoutError:
        self.auto_compact.check_expired(
            self._schedule_background,
            active_session_keys=self._pending_queues.keys(),
        )
        continue
```

`check_expired()` 遍历所有会话，跳过以下情况：
- 已在归档中的会话（`key in self._archiving`）
- 有活跃任务的会话（`key in active_session_keys`）
- 未过期的会话（`updated_at` 距今未超过 `session_ttl_minutes`）

---

### 第二步：过期判断

`_is_expired()` 检查会话的 `updated_at` 时间戳：

```python
def _is_expired(self, ts, now=None) -> bool:
    if self._ttl <= 0 or not ts:
        return False  # TTL=0 表示禁用
    return ((now or datetime.now()) - ts).total_seconds() >= self._ttl * 60
```

通过配置 `idleCompactAfterMinutes` 设置阈值（默认 0，即禁用）。

---

### 第三步：后台归档（`_archive()`）

对过期会话，将其加入 `_archiving` 集合并调度后台任务：

```
_archive(key)
├── sessions.invalidate(key)          # 清除内存缓存，强制从磁盘重新加载
├── sessions.get_or_create(key)       # 加载最新会话状态
├── _split_unconsolidated(session)    # 分割消息
│   ├── 取出 session.messages[last_consolidated:] 的尾部
│   ├── 保留最近 8 条消息（_RECENT_SUFFIX_MESSAGES）
│   └── 其余消息作为待归档前缀
├── consolidator.archive(archive_msgs) # 调用 LLM 总结旧消息
├── 保存摘要到两处：
│   ├── self._summaries[key] = (summary, last_active)  # 内存（进程内）
│   └── session.metadata["_last_summary"] = {...}       # 磁盘（跨重启）
├── session.messages = kept_msgs      # 只保留最近 8 条
├── session.last_consolidated = 0     # 重置偏移量
└── sessions.save(session)            # 持久化
```

---

### 第四步：摘要注入（`prepare_session()`）

当用户再次发送消息时，`_process_message()` 调用 `prepare_session()` 准备会话：

```python
def prepare_session(self, session, key) -> tuple[Session, str | None]:
    # 优先从内存获取（进程未重启）
    entry = self._summaries.pop(key, None)
    if entry:
        session.metadata.pop("_last_summary", None)
        return session, self._format_summary(entry[0], entry[1])
    # 其次从元数据获取（进程重启后恢复）
    if "_last_summary" in session.metadata:
        meta = session.metadata.pop("_last_summary")
        self.sessions.save(session)
        return session, self._format_summary(meta["text"], ...)
    return session, None
```

摘要格式为：
```
Inactive for 25 minutes.
Previous conversation summary: <LLM 生成的摘要内容>
```

这段摘要作为**一次性运行时上下文**注入系统提示，消费后立即清除，不会重复出现。

### 关键设计要点

| 特性 | 说明 |
|------|------|
| **触发方式** | 寄生在主循环超时路径，无独立定时器 |
| **保留消息数** | 最近 8 条（`_RECENT_SUFFIX_MESSAGES`）|
| **摘要持久化** | 同时写内存和磁盘元数据，进程重启后可恢复|
| **摘要一次性** | `pop()` 消费后清除，不会重复注入 |
| **任务感知** | 跳过有活跃 pending_queue 的会话，避免干扰正在进行的对话 |
| **默认禁用** | `idleCompactAfterMinutes=0` 时完全不触发 |
