
## 何时创建子代理？

子代理在以下情况下创建：

### 1. LLM 决定使用 spawn 工具时

当主代理的 LLM 判断需要处理**复杂或耗时的独立任务**时，会调用 `spawn` 工具：

```python
return (
    "Spawn a subagent to handle a task in the background. "
    "Use this for complex or time-consuming tasks that can run independently. "
    "The subagent will complete the task and report back when done. "
    "For deliverables or existing projects, inspect the workspace first "
    "and use a dedicated subdirectory when helpful."
)
```

### 2. 典型使用场景

- **长时间运行的任务**：如大型代码分析、批量文件处理
- **独立的研究任务**：如搜索网络资源、分析日志文件
- **可并行的子任务**：如同时检查多个项目的状态

### 3. 创建流程

1. LLM 在响应中包含 `spawn` 工具调用
2. `SpawnTool.execute()` 被调用，传递任务描述和可选标签
3. 调用 `SubagentManager.spawn()` 创建后台任务
4. 生成 8 字符 task_id，创建 `asyncio.Task` 在后台执行
5. 主代理立即返回确认消息给用户

### 4. 关键限制

- 子代理**不能递归创建**更多子代理（工具集中不包含 `spawn`）
- 子代理最大迭代次数限制为 15 次
- 子代理完成后通过消息总线将结果注入回主对话

## Notes

- 创建决策完全由 LLM 基于任务复杂度自主做出
- 主代理使用 ContextVar 跟踪原始会话上下文，确保结果正确路由
- 测试显示子代理可以处理文件系统、shell 执行和 Web 搜索等任务
