# AgentRunner 概述

AgentRunner 是 nanobot 的核心执行引擎，负责运行支持工具的 LLM 循环，不涉及产品层逻辑 。

## 核心职责

AgentRunner 处理 LLM 交互的低层机制，包括：
- 工具结果预算管理
- 历史消息裁剪以适应上下文窗口
- 多轮工具执行逻辑
- 中途消息注入（mid-turn injection）

## 主要组件

### AgentRunSpec 和 AgentRunResult

- **AgentRunSpec**: 单次执行的配置，包含初始消息、工具、模型等参数
- **AgentRunResult**: 执行结果，包含最终内容、使用的工具、使用量统计等

### 核心执行流程

`run` 方法是主要入口点，执行以下步骤 ：

1. **上下文治理**: 清理孤立工具结果、应用工具结果预算、裁剪历史
2. **LLM 请求**: 调用提供商获取响应
3. **工具执行**: 如果有工具调用，并行执行工具
4. **注入检查**: 在多个关键点检查并处理中途注入的消息

### 中途消息注入

AgentRunner 在多个阶段检查注入消息：
- 工具执行后
- 最终响应后
- 错误发生时

通过 `_try_drain_injections` 方法处理注入，有最大周期限制防止无限循环。

### 错误处理与恢复

- **空响应重试**: 最多 2 次静默重试
- **长度恢复**: 当响应过长时的恢复机制
- **工具错误处理**: 可配置是否因工具错误而失败

## 使用场景

### 在 AgentLoop 中使用

AgentLoop 创建 AgentRunner 实例来处理消息 ：

```python
self.runner = AgentRunner(provider)
```

### 在 SubagentManager 中使用

子代理也使用 AgentRunner，但配置更严格的限制：
- 最大 15 次迭代
- 工具错误时失败
- 简化的钩子实现

## 高级特性

### 并发工具执行

支持并行执行工具以提高效率 。

### 流式响应支持

通过钩子机制支持流式输出 。

### 检查点机制

支持在关键点保存检查点，用于恢复状态。

## Notes

- AgentRunner 是无状态的，每次调用都是独立的执行
- 它不直接与消息总线交互，这是 AgentLoop 的职责
- 测试覆盖了各种场景，包括注入、错误恢复、并发等
