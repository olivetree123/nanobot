# Dream 概述

Dream 是 nanobot 内存系统的核心组件，负责将对话历史转化为长期知识。

## 核心功能

Dream 实现两阶段的内存处理：
1. **Phase 1（分析）**：研究新的历史条目与现有知识的关系
2. **Phase 2（编辑）**：通过 AgentRunner 执行精确的文件更新

## 工作流程

### 数据源
Dream 处理以下文件：
- `memory/history.jsonl` - 新的对话历史
- `SOUL.md` - 机器人个性
- `USER.md` - 用户信息  
- `MEMORY.md` - 项目知识

### 执行过程
1. 读取未处理的历史条目（从 `.dream_cursor` 位置开始）
2. Phase 1：使用 `dream_phase1.md` 模板分析内容
3. Phase 2：使用 `dream_phase2.md` 模板指导文件编辑
4. 通过 GitStore 提交更改

## 配置

Dream 通过 `DreamConfig` 类配置：

```json
{
  "agents": {
    "defaults": {
      "dream": {
        "intervalH": 2,
        "modelOverride": null,
        "maxBatchSize": 20,
        "maxIterations": 10
      }
    }
  }
}
```

## 集成与调度

### 自动执行
Dream 作为系统任务注册到 cron 服务：
- 默认每 2 小时运行一次
- 可通过 `intervalH` 调整频率

### 手动触发
通过 `/dream` 命令立即执行。

## 关键特性

### 工具集成
Dream 使用专门的工具集进行文件操作：
- `read_file` - 读取文件
- `edit_file` - 编辑文件
- `write_file` - 创建新技能

### 技能创建
Dream 可以将重复的工作流程转化为可重用的技能。

### 版本控制
所有更改通过 GitStore 自动提交，支持审计和回滚。

## 管理命令

- `/dream` - 立即运行 Dream
- `/dream-log` - 查看最近的更改
- `/dream-restore` - 恢复到之前的版本

## Notes

- Dream 是 nanobot 内存系统的第二阶段，Consolidator 是第一阶段
- Dream 只处理新的历史条目，避免重复工作
- 测试覆盖了各种场景，包括技能创建、文件编辑等
