# 清理孤立工具结果是什么意思，为什么会有孤立的工具结果？

## 什么是孤立工具结果

孤立工具结果（orphan tool results）是指那些在消息历史中没有对应助手工具调用（assistant tool_call）的工具结果消息。正常情况下，工具调用流程应该是：
1. Assistant 发送包含 `tool_calls` 的消息
2. 系统执行工具并返回 `tool` 角色的结果消息
3. 每个工具结果都有对应的 `tool_call_id`

当工具结果消息失去了对应的助手工具调用时，就成为了"孤立"状态。

## 为什么会产生孤立工具结果

### 1. 历史消息裁剪
当上下文窗口超出限制时，`_snip_history` 方法会裁剪旧消息。如果裁剪了包含 `tool_calls` 的助手消息，但保留了对应的工具结果，就会产生孤立结果。

### 2. 消息序列化/持久化问题
在消息的序列化、反序列化或持久化过程中，可能出现数据不一致的情况。

### 3. 并发处理异常
在复杂的工具执行流程中，如果发生异常或中断，可能导致消息状态不一致。

## nanobot 的处理机制

### 清理孤立结果
`_drop_orphan_tool_results` 方法会扫描消息历史，移除那些没有对应 `tool_call_id` 的工具结果消息：

```python
if role == "tool":
    tid = msg.get("tool_call_id")
    if tid and str(tid) not in declared:
        # 跳过这个孤立的工具结果
        continue
```

### 补充缺失结果
相反地，如果发现有 `tool_calls` 但没有对应的工具结果，`_backfill_missing_tool_results` 会插入合成错误结果：

```python
updated.insert(insert_at, {
    "role": "tool",
    "tool_call_id": call_id,
    "name": name,
    "content": _BACKFILL_CONTENT,
})
```

### 上下文治理流程
这些清理操作在每次迭代的上下文治理阶段执行，确保发送给 LLM 的消息历史是完整和一致的。

## Notes

- 这种机制确保了 LLM 始终看到完整的工具调用链，避免混淆
- 测试显示即使在裁剪后也能正确清理孤立结果
- 这些操作只影响发送给模型的消息副本，不会改变实际保存的会话历史
